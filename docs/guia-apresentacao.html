01.Visão Geral

O Mempool Miner é um jogo de caça-palavras onde as palavras não são inventadas: elas nascem de transações reais da mempool Bitcoin. Cada transação que entra na rede vira uma palavra BIP39 (derivada do TXID), e o jogador tem um cronômetro para encontrá-las numa grade de letras. Quanto mais rápido e com mais combos, mais sats (a moeda do jogo) você ganha.

⛏️ O LOOP CENTRAL

Transação entra na mempool → vira palavra → aparece na grade → você encontra antes do tempo acabar → ganha sats + XP. Bloco novo = rodada nova.

₿ MOEDA

Sats são 100% simulados (Redis). Você começa com 0. Ganha jogando, em missões, crates, mercado e staking. Gasta em energia, upgrades, crates e mercado.

🌐 REDES

Regtest (local, com faucet), Signet (pública) e Mainnet (opcional). A mecânica é idêntica; muda a origem das transações.

🏆 PROGRESSÃO

XP por palavra → níveis → ranks → pontos de skill. Season Pass trimestral com trilhas free/premium. Leaderboard resetado a cada 2016 blocos.

02.Início Rápido (passo a passo)

Guia do primeiro acesso à primeira rodada. Não há tutorial in-game — este é o passo a passo.

  1. Abra o jogo e escolha a rede No modal SYSTEM_AUTHENTICATION, selecione a rede no dropdown. Regtest é a mais rápida para começar (tem faucet local). Signet usa mempool pública real. Mainnet aparece desativada se o profile mainnet não estiver rodando.
  2. Defina seu OPERATOR_ID Nome de 1 a 12 caracteres (letras, números, _ e -). Se deixar vazio, o jogo gera Miner_XXXX aleatório. Opcional: escolha um POOL/GUILDA (aparece no leaderboard de pools).
  3. Clique em EXECUTE_NODE O backend valida a rede (precisa estar playable), cria seu estado de jogador (saldo 0, hardware nível 1, energia 10/10) e abre o WebSocket. Se a rede estiver sincronizando, o jogo mostra o progresso e tenta de novo a cada 10s.
  4. Aguarde a primeira grade O jogo coleta 6 palavras da mempool (eventos transaction_received) e monta a grade 12×12. O cronômetro parte de 60s (+ bônus de hardware/nível/skill).
  5. Encontre as palavras Selecione letras na grade (arrastando ou clicando). Palavras andam para →, ↓, ↘ e ↙. Encontre as 6 antes do tempo acabar. Cada palavra dá sats + XP. Erros consecutivos (3+) custam 5% do saldo (slashing).
  6. Bloco novo = rodada nova Quando um bloco é minerado, a rodada atual encerra (ou você pode pagar 100.000 sats pelo RBF para resgatar +15s). Uma nova grade é montada com as 6 palavras do próximo bloco.
  7. Gaste seus sats Na tab UPGRADES: compre hardware (+10s por nível), energia (2.000 sats → +3), crates (5.000 sats → loot) ou L2 Lightning (1.000.000 sats → modo 8×8 com 10× recompensas).
DICA DE NOJO
Palavras GOLDEN (douradas, 5×) e HIGH FEE (laranja, 3×) valem muito mais. Priorize-as. Palavras MEV são ocultas no word bank — se encontrar uma que não está listada, são +50.000 sats.

03.Jogo Central (tab JOGO)

3.1 Geração de palavras: do TXID ao BIP39

A palavra do jogo é uma função pura do TXID — determinística e independente do nó. O mesmo TXID gera a mesma palavra em qualquer instância do jogo.

EtapaOndeDetalhe
TXID calculadoingestor.py:446-450Double SHA256 do hex da transação + reversão de bytes (formato Bitcoin).
Entropiaengine.py:92bytes.fromhex(txid[:32]) — primeiros 128 bits (32 hex) do TXID.
Palavra BIP39engine.py:93Mnemonic("english").to_mnemonic(entropy).split()[0].upper() — primeira palavra do mnemonic BIP39 inglês, em MAIÚSCULAS.
Fallbackengine.py:94-96TXID inválido → "BITCOIN".
Validação frontendgame.js:1176-1190word deve casar /^[A-Z]{1,15}$/; is_high_fee/is_golden booleanos; vsize número > 0.

A palavra viaja no evento transaction_received com os campos: word, txid, tx_stub (8 hex), is_golden, is_high_fee, vsize, fee_rate_sat_vb, is_mev, base_reward (500), multiplier.

RBF / transação minerada

EventoComportamento
Bloco minerado (backend)Epoch avança para o novo block_hash; transações da epoch anterior são drenadas (drain_stale_transactions, ingestor.py:293-321); publica block_mined com is_halving_block = blocks % 210000 == 0.
Bloco minerado (frontend)Dedup por block_hash/epoch; limpa o buffer de transações; se estiver jogando → oferece Orphan Block Salvage (RBF) uma vez por rodada; senão → prepara o próximo bloco.
RBF (resgate)Custa 100.000 sats e concede +15s (RBF_PRICE/RBF_TIME_BONUS, game.js:3100-3101). Aceitar em 3s reinicia a rodada com 15s + bônus; recusar/expirar encerra a rodada.

Dedup (evitar palavras repetidas)

CamadaMecanismo
Backend (TXID)Set Redis de TXIDs já publicados por epoch ({realm}:seen:{epoch}), TTL 3600s. Se o TXID já foi publicado, a transação não é reenviada.
Frontend (palavra)Ignora palavra duplicada no buffer da rodada (game.js:1649).
Frontend (bloco)Ignora block_mined com block_hash/epoch já processado (re-entrega ZMQ).

Posicionamento das palavras

  • Direções de injeção: [[1,0],[0,1],[1,1],[1,-1]] — horizontal →, vertical ↓, diagonal ↘, diagonal ↙ (sem reversas).
  • Validação da seleção: mesmas 4 direções, mas bidirecional (normaliza caminho forward/reverse).
  • injectWordInGrid: até 200 tentativas aleatórias; fallback determinístico (scan horizontal por linha vazia). Palavras maiores que o grid são truncadas.
  • fillGridWithoutIncidentalWords: letras A-Z aleatórias, até 50 tentativas, rejeita se o filler criar uma palavra-alvo acidental.
  • buildPlayableBlock tenta até 4 vezes; se falhar, "Falha ao montar a grade".

Fórmula completa

points = (
    (effectiveBaseReward × (1 + skillRewardBonus))   # base ajustada por halving/evento/skill
    + (word.length × 50)                              # bônus por comprimento
) × comboMultiplier                                   # combo (1.0–4.0, 6.0 c/ Double Combo)
  × backendMultiplier                                 # golden 5× / high_fee 3× / golden+high_fee 15×
  [× 10 se lightningMode]
  [× 1.5 se magnet]
  = applyAchievementBonus(points)                    # floor(points × (1 + reward_percent))

balanceSatoshis += floor(points)                     # game.js:2868
currentRoundEarnings += floor(points)                # game.js:2867

Bônus fixos (fora da fórmula): MEV +50.000 sats; Boss loot +50.000 sats.

Slashing (penalidade): 3+ erros consecutivos → 5% do saldo debitado. Power-up Precision isenta a rodada.

XP por palavra: Math.round(word.length × 10 + comboMultiplier × 5). O XP vai simultaneamente para o nível do jogador e para o season pass.

Score no leaderboard: submitScore() envia balanceSatoshis (saldo total) como score, após cada palavra.

OBSERVAÇÃO
Não há "bônus de tempo restante" no fim da rodada. O "bônus de tempo" refere-se ao tempo extra concedido por hardware/nível/skill (seção 3.7), não a um acréscimo de sats por tempo sobrando.

4.6 Mercado P2P (tab SOCIAL)

  • Taxa: 5% cobrada na compra — comprador paga preço + 5%, vendedor recebe preço − 5%. Venda não cobra taxa.

4.8 Faucet regtest

Configuração: FAUCET_INTERVAL=20s, FAUCET_TXS=12, BLOCK_INTERVAL=90s. A cada 20s: 12 transações de 0,001 BTC; a cada 90s: 1 bloco minerado. Papel na economia: regtest não tem tráfego orgânico — o faucet é a ÚNICA fonte de transações da mempool (que viram palavras) e de blocos frescos (disparam block_mined: crates grátis, boss blocks). Não é fonte de sats — os sats são 100% simulados (Redis); o faucet é infraestrutura de dados, não de moeda.

05.Progressão

5.1 XP

  • Por palavra (única fonte de XP): baseXP = word.length × 10; comboBonus = comboMultiplier × 5; Math.round(baseXP + comboBonus). O XP vai simultaneamente para o nível do jogador e para o season pass.
  • Rodada/bônus: NÃO há XP por rodada completa nem por bônus (MEV, boss, golden).
  • Combo: começa 1.0, +0.5 a cada palavra em <8s, teto 4.0 (6.0 com power-up double_combo).
  • Curva de nível: xp_to_next_level(level) = level × 100 (linear, sem teto). XP total p/ nível N = 100·N·(N−1)/2.
  • Curva de season: fixa SEASON_XP_PER_LEVEL = 100, teto nível 40.
  • Bug float (corrigido): int(float(xp_amount)) no season pass e Math.round no frontend. Endpoint de nível ainda vulnerável — grava str(xp) sem coerção; mitigado só pelo Math.round do frontend.

5.3 Season Pass

  • Duração real: trimestre (Q1→04/01, Q2→07/01, Q3→10/01, Q4→01/01). Season ID: season_{ano}_q{trimestre}.
  • Estrutura: 20 níveis free + 20 premium (níveis 21–40). XP_PER_LEVEL = 100.
  • Premium: 50.000 sats, compra atômica Lua.
  • Recompensas free (1–20): sats 500→25.000, hints 1/2/3 (nív. 3, 9, 15), power-ups scanner (6), time_freeze (12), magnet (18), nível 20: 25.000 sats + season_badge.
  • Recompensas premium (21–40): sats 30.000→250.000, cards rare (22, 38), epic (26, 34), legendary (30), power-ups precision (24), double_combo (28), scanner (36), bônus reward_plus_5pct 7d (32) e reward_plus_10pct 14d (40).
  • Claim: Lua — só credita sats, hint, powerup. Tipos card, bonus, season_badge são marcados como reclamados sem creditar nada (ponta solta ALTO).
  • Fim da temporada: nenhuma lógica de rollover/claim-deadline; chave com TTL 30 dias.

Como se ganha: (a) bloco — todo jogador conectado recebe via WS block_mined → creditBlockCard; (b) crate — 12% rare/epic; (c) season premium — níveis 22/26/30/34/38 (não implementado no claim); (d) mercado — não existe para cards. Bônus de coleção: common 10→+1%, rare 5→+2%, epic 3→+3%, legendary 1→+5% (calculado, mas aplicação nas recompensas não verificada). Sem efeito individual por card.

5.6 Missões

Ver §4.4 para a tabela de recompensas. Painel na tab COMPETIR. Progresso: POST /update. Claim: POST /claim/{mission_id} (correção: persist() em vez de expire(86400)). TTL da chave de missões: 8 dias. Ponta solta: 10_words_no_error usa stat cumulativo words_found — "consecutivas sem erro" não é rastreado.

5.7 Leaderboard

  • Global: ZADD GT CH, top 10. Pools: ZADD GT CH por pool_name, top 10.
  • Score: balanceSatoshis (saldo total), enviado após cada palavra.
  • Reset por epoch: a cada 2016 blocos — del leaderboard + pools, incrementa epoch_id, publica leaderboard_reset. Frontend: "Nova temporada! Leaderboard resetado".
  • Sprint: leaderboard separado, ordenado por menor tempo.

06.Sistemas Transversais

6.1 Eventos Globais

Eventos aleatórios que alteram as regras do jogo para todos os jogadores do realm. O scheduler roda em cada instância do backend; lock Redis (SET NX) garante 1 instância por realm. Intervalo entre eventos: aleatório 30–60 min. Pre-anúncio declarado: 120s.

EventoÍconeDuraçãoEfeito anunciado
Fee Spike⚡600s (10 min)Todas as palavras High Fee, 3×
Golden Rush🌟300s (5 min)Golden Hash 3× mais frequente, 5×
Mempool Flood🌊600s (10 min)Grade 15×15 obrigatória, 2×
Lightning Storm⛈️180s (3 min)Lightning Mode para todos, 10×, 8×8

Efeitos no backend (apply_event_effects): fee_spike → is_high_fee=True, multiplier 3× (15× se golden); golden_rush → ~30% das palavras viram golden (5×); mempool_flood → multiplier ×2; lightning_storm → multiplier ×10. Efeitos no frontend (buildPlayableBlock): sobrepõe grade/tempo/multiplicador — Lightning Storm → 8×8/20s/×10; Mempool Flood → 15×15/75s/×2; Fee Spike → ×3; Golden Rush → ×5.

Notificação: banner #global-event-banner com countdown 1s; pre-anúncio mostra "…em breve!"; ao iniciar sessão, loadActiveGlobalEvent() via REST reconecta o banner se evento já ativo.

⚠ PONTA SOLTA (ALTO)
Double-counting de multiplicadores: o backend aplica o multiplicador do evento no multiplier da TX e o frontend aplica globalRewardMultiplier no effectiveBaseReward. Resultado: Fee Spike → 3××3× = 9× (deveria ser 3×); Golden Rush → 5××5× = 25×; Mempool Flood → 2××2× = 4×; Lightning Storm → 10××10× = 100×. Além disso, o timing do pre-anúncio está quebrado (publicado no mesmo instante do trigger, não 2 min antes).

6.6 Resiliência

  • Backend fora do ar: retry com backoff exponencial — 5 tentativas, delay = 1000 × 2^(n−1) (1s, 2s, 4s, 8s, 16s); após 5 falhas → "Falha na reconexão. Recarregue a página."
  • WebSocket inativo: timeout de 300s sem mensagem do cliente → encerra; heartbeat do servidor (30s) permite ao cliente detectar inatividade.
  • Rede do navegador: navigator.onLine → offline desabilita catálogo ("Sem conexão"); ao voltar online, recarrega catálogo.
  • PWA: service worker registrado com atualização sob decisão do jogador.
  • Backpressure: fila do relay cheia (1000) → evento descartado com warning.

Singleton por rede

O ingestor é um singleton por realm_id — cada rede tem seu próprio listener ZMQ, fila, dedup e epoch. Trocar a fonte de dados (ex.: API pública em vez de ZMQ local) afeta apenas o "producer"; todo o resto do pipeline (dedup, epoch, lease, PubSub, WebSocket, frontend) permanece intacto. A palavra é função pura do TXID, então é agnóstica à fonte.
